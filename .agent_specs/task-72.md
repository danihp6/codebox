## 🎯 Scope

- **Task type:** daemon (three new subsystems, one selection shared with the scheduler, one
  commit seam). No app work, no ops work.
- **Role:** Dev.
- **Objective:** after this task the daemon serves the D44/D51/D55/D56 model. A **work** is one
  backlog item of one repository: it can be created from a `Task-NN` ref, read back with its
  runs, started, interrupted and marked reviewed. `GET /v1/repos/{id}/backlog` projects the
  repository's `TODO.md` at the default branch, joined with the works that came from it. A
  **session** is an editor with exactly one target (`backlog`/`design`/`schedule`/`work`/`repo`),
  and its target is its write boundary: a proposal outside it is refused with
  `target_violation`, before the branch is pushed. One selection function, built on
  `@codebox/backlog`, decides what the scheduler's fire and `POST /v1/repos/{id}/run-next` pick,
  and the run's own commit flips exactly one checkbox of the item it came from.
- **Environment:** worktree `../wt-cb-72`, branch `task-72`, base `main` at `5724a6c`.

### 2. `apps/daemon/src/backlog/` — the file, the projection, the selection

```ts
export interface BacklogSnapshot {
  readonly markdown: string;
  /** The commit the file was read at: `git rev-parse <defaultBranch>` in the bare clone. */
  readonly revision: string;
}

export interface BacklogRuntime {
  readSnapshot(repo: Repo): Promise<BacklogSnapshot>;
  /** `origin/<defaultBranch>:TODO.md` through `git show`, in the repository's bare clone. */
}

export interface BacklogService {
  /** `null` when the repository has no `TODO.md` at its default branch. */
  read(repo: Repo): Promise<BacklogSnapshot | null>;
  /** docs/api.md §5.6: the parsed file joined with the works that came from it. */
  project(repo: Repo): Promise<Backlog | null>;
  /** Throws `BacklogRefError` (below) when the ref is unknown, ambiguous or already ticked. */
  resolveItem(repo: Repo, ref: BacklogRef): Promise<{ item: BacklogEntry; revision: string }>;
  /** docs/jobs.md §16: the one selection. `maxAttempts` comes from the caller. */
  select(
    repo: Repo,
    policy: Omit<SelectionPolicy, 'maxAttempts'> & { maxAttempts: number },
  ): Promise<SelectionResult>;
  /** Flips one checkbox in the worktree's `TODO.md`; never reformats another byte. */
  tick(worktree: string, ref: BacklogRef): Promise<TickOutcome>;
}

export type BacklogRefReason = 'backlog_ref_missing' | 'backlog_ref_ambiguous' | 'backlog_ref_checked';
export class BacklogRefError extends Error {
  readonly reason: BacklogRefReason;
}
```

- `project` maps each `BacklogEntry` to `backlogItemSchema` (`{ref, title, checked, line, work}`)
  and groups by `BacklogEntry.section`, in file order. `work` comes from
  `store.works.findByBacklogRef(repo.id, ref)` and is `{ id, state, runs }` where `runs` is the
  number of run rows for that work (`store.runs.list({ workId })`, see §5) — `0` when the work
  has none. `revision` is `BacklogSnapshot.revision`; `path` is `'TODO.md'`. A repository with
  no `TODO.md` answers `200` with `{ repoId, revision, path, sections: [] }` and
  `revision` = the default-branch sha.
- `select` reads the snapshot, `parseBacklog`s it, and calls `selectNextItem(items, works,
  policy)` where `works` is `BacklogWorkState[]` built from the repository's works
  (`store.works.list({ repoId, limit: 500, cursor: null })` pages until exhausted):
  `{ ref: work.backlogRef, state: work.state, attempts: work.attempts }`. The package owns the
  rule; this module only feeds it.
- `tick` reads `TODO.md` in the worktree with `node:fs`, calls `applyTick`, writes the file back
  **only** when the outcome is `ticked`, and returns the outcome unchanged. `missing` and
  `ambiguous` change nothing on disk.
- Route: `GET /v1/repos/{id}/backlog`, scope `read`, `404 not_found` with
  `details.path = 'repo.id'` for an unknown repository. It never writes.

### 3. `apps/daemon/src/works/` — the unit

Routes (`docs/api.md` §5.6), scopes as written there:

| Method | Path | Behaviour |
| --- | --- | --- |
| `GET` | `/v1/works?repoId=&state=` | `store.works.list`, the §4 page. `200`. |
| `POST` | `/v1/works` | `{ repoId, backlogRef }` → `resolveItem`; unknown/ambiguous ref is `422 validation_failed` with `details.path='work.backlogRef'` and `details.reason` = the `BacklogRefError` reason; a ticked item is `409 conflict` with `details.reason='backlog_ref_checked'`. Writes a `Work` with `state:'queued'`, `origin:'backlog'`, `title` = item title, `prompt` = item `body`, `specSha` = revision, `attempts:0`, `maxAttempts:2`, usage zero, `contextEpoch:1`, `reviewedAt:null`. `201`. |
| `GET` | `/v1/works/{id}` | `WorkDetail` = `{ work, repo, runs }`, the runs of that work newest first. `404` otherwise. |
| `PATCH` | `/v1/works/{id}` | `{ title?, prompt? }` → `409 conflict`, `details.reason='spec_in_git'` whenever either key is present (D51: the file owns those fields). An empty body is `422 validation_failed`. |
| `DELETE` | `/v1/works/{id}` | `state → 'abandoned'`, `204`. |
| `POST` | `/v1/works/{id}/runs` | `{ prompt? }` → one new run through `queueRun` with `workId: work.id`, `title` = work title, `prompt` = body `prompt` ?? `work.prompt`; the work goes `running` and `attempts` + 1. `202` with the `Run`. |
| `POST` | `/v1/works/{id}/decision` | creates a session `{ target:'work', workId }` (`sessions` service) and sets the work `needs_decision`. `201` with the `Session`. |
| `POST` | `/v1/works/{id}/reviewed` | sets `reviewedAt` **once**; a second call is `409 conflict`, `details.reason='already_reviewed'`. `200` with the `Work`. |
| `POST` | `/v1/works/{id}/interrupt` | cancels the live run through `RunEngine.cancel(runId, 'operator')`; `409 conflict` `details.reason='no_live_run'` when there is none. `202`. |
| `POST` | `/v1/repos/{id}/run-next` | the §2 `select` with `{ selection:'nextPending', refs:[], maxAttempts: repo schedule's maxAttempts ?? 2 }`. `selected` → one work (`origin:'schedule'` is wrong here: use `'manual'`) plus one run, `202` with the `Run`; `nothing_pending`/`nothing_runnable` → `409 conflict` with `details.reason` = the selection kind. A repository with no schedule still works. |

- `store.works` has no `findByBacklogRef` filter for *listing*: the repository index is
  `(repo_id, backlog_ref)`. Use `findByBacklogRef` for the one look-up, and `list` for the
  backlog projection and the selection feed.
- `queueRun`'s input grows `workId?: string | null`; `runs/service.ts` writes it on the run row
  and passes it to the engine (`RunStartInput.workId`). Nothing else in `queueRun` changes.

### 4. `apps/daemon/src/sessions/` — the target is the boundary

Routes (`docs/api.md` §5.6.1): `GET /v1/sessions?repoId=&target=`, `POST /v1/sessions`,
`GET /v1/sessions/{id}`, `GET /v1/sessions/{id}/messages?cursor=`,
`POST /v1/sessions/{id}/messages`, `POST /v1/sessions/{id}/compact`,
`POST /v1/sessions/{id}/merge`, `POST /v1/sessions/{id}/interrupt`,
`DELETE /v1/sessions/{id}`.

The one rule this task exists to enforce, in `apps/daemon/src/sessions/service.ts`:

```ts
/** The only paths a target may write. `repo` writes nothing; `work` writes the backlog only. */
export const TARGET_WRITE_SETS: Readonly<Record<SessionTarget, readonly string[]>> = Object.freeze({
  backlog: ['TODO.md'],
  work: ['TODO.md'],
  design: ['design/'],
  schedule: ['.codebox/schedule.yml'],
  repo: [],
});

/** `null` when every path is inside the target, else the first path that is not. */
export function outsideTarget(target: SessionTarget, paths: readonly string[]): string | null;
```

- `outsideTarget('design', ['design/tokens.json'])` → `null`;
  `outsideTarget('design', ['apps/app/src/theme/tokens.ts'])` → `'apps/app/src/theme/tokens.ts'`;
  `outsideTarget('backlog', ['TODO.md'])` → `null`; `outsideTarget('backlog', ['docs/api.md'])`
  → `'docs/api.md'`; `outsideTarget('repo', ['TODO.md'])` → `'TODO.md'`.
- The **proposal** is the only way a session writes: `POST /v1/sessions/{id}/merge` reads the
  session's worktree diff (`git diff --name-only <baseSha>` through the injected git runner) and
  refuses `409 conflict` with `details.reason='target_violation'` and
  `details.path=<first offending path>` before it pushes or merges anything. A second proposal
  while one is pending is `409` `details.reason='proposal_pending'`; a merge with none is `409`
  `details.reason='proposal_none'`; a merge on `target:'repo'` is `409`
  `details.reason='read_only_session'`.
- `POST /v1/sessions` validates `target`, and `workId` is non-null **exactly** when
  `target === 'work'` (the table's `CHECK` enforces it too): otherwise `422 validation_failed`
  with `details.path='session.workId'`. `design`, `backlog` and `work` sessions get a worktree
  and a `cb/` branch; `repo` gets the worktree and a `null` branch and no proposal.
- `POST /v1/sessions/{id}/messages` appends the user `SessionMessage`, marks the session
  `working`, then runs **one** agent turn through `createAgentRuntime` (same options as
  `../runs/engine.ts`), appends the assistant message, marks it `idle`, updates `usage` and
  `contextTokens`, and appends one `session.message` event per persisted message with
  `store.events.nextSeq({ sessionId })`. A runtime failure ends the turn with
  `502 agent_unavailable` **after** the user message is stored, and leaves the session `idle`.
  The turn is awaited: no floating promise outlives the request.
- `POST /compact` starts a new agent session in the same worktree and bumps `contextEpoch`.
  `POST /interrupt` stops the turn and returns the session to `idle`.
- `DELETE` archives (`status:'archived'`) and answers `204`.

### 5. The one selection in the fire, and the tick in the commit

- `apps/daemon/src/schedules/fire.ts`: `ScheduleFirePort` loses `startChat` and its
  `chat*` errors. `startRun` becomes async and takes `{ schedule, scheduledFor }`; it calls the
  §2 `select` with `{ selection: schedule.selection, refs: schedule.refs, maxAttempts:
  schedule.maxAttempts }`, creates the work (`origin:'schedule'`) and queues one run with the
  item's `body` as the prompt, then writes `scheduledFor` on the run row exactly as today.
  `ScheduleFireErrorCode` becomes
  `'repo_required' | 'repo_missing' | 'backlog_unavailable' | 'provider_exhausted' | 'internal'`
  — **`provider_exhausted` is required by Task-73** and `internal` must exist for the
  unexpected case. A selection that finds nothing is **not** an error: the fire row ends
  `nothing_pending`, or `nothing_runnable` when every candidate was refused, and
  `schedules/service.ts` (out of your paths) keeps its current finish path — adapt the fire
  port so the service still finishes the row, and if the service cannot express it without a
  change outside your paths, record that in `docs/api.md` §5.6 note and in your report.
- `packages/store/src/runs.ts`: `RunFilter` gains `workId?: string`, applied as a `WHERE
  work_id = ?` next to the other filters, with a test. Nothing else in the store changes.
- `apps/daemon/src/run/ports.ts` + `engine.ts` + `commit.ts`: `RunStartInput` gains
  `workId?: string | null` and `backlogRef?: string | null`; `commit.ts`'s `CommitInput` gains
  `tick?: { readonly path: string; readonly ref: BacklogRef } | null`. In `openPullRequest`,
  **before** the `commitsAhead === 0` check, when `tick` is set, call
  `tickWorktreeItem`-equivalent (`applyTick` + write) and then commit whenever the file changed
  or the index was already dirty. The commit subject stays `ctx.input.title`; the body stays
  `Codebox-Run: <runId>`. An `ambiguous` or `missing` tick commits nothing and logs one
  `backlog_tick_skipped` line with the reason; it never fails the run.

### Data

- `works` row: `{ id: wrk_*, repoId, backlogRef, title, prompt, specSha, state, origin,
  attempts, maxAttempts, usage, contextTokens, contextEpoch, reviewedAt, createdAt,
  updatedAt }` — exactly `workSchema`.

  second `POST /v1/works` for a ref with a `queued`/`running`/`needs_decision` work is
  `409 conflict` with `details.reason='live_work'` (map the store's unique violation).
