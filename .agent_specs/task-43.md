## 🔒 Contract

This is the public surface QA and the operator are written against. Names, flags, exit codes,
log lines and object keys are frozen.

### `ops/vm/backup.sh`

```
usage: backup.sh [--db FILE] [--out DIR] [--recipient AGE_RECIPIENT] [--plaintext]
                 [--verify] [--upload] [--fetch KEY] [--s3-uri URI] [--root DIR] [--help]
```

Unchanged behaviour (keep every existing test green):

- one consistent SQLite snapshot, a redacted `instance.env`, a `manifest.json` with
  `{ version, createdAt, dbBytes, encrypted }`, archived as `state.db manifest.json instance.env`;
- local names `cb-backup-<YYYYMMDDTHHMMSSZ>.tar.gz` (plaintext) or `.age` (default), mode
  `0640`, under `--out` (default `/var/lib/codebox/backups`);
- `--verify` decrypts the newest local archive and prints `verify ok runs=<n> jobs=<n> routines=<n>`;
- `--plaintext` never uploads; `--upload` with `--plaintext` is still `exit 2` with
  `CB_BACKUP_AGE_RECIPIENT is empty` (unchanged message);
- a missing database is `exit 6` with `no database at <path>`.

New behaviour:

- **`--upload`** (`CB_BACKUP_S3_URI` or `--s3-uri`) runs **after** the archive is written and
  `archive <path>` is printed to stdout:
  1. write `<archive>.sha256` next to the archive, content exactly `<lowercase hex><two spaces><basename>\n`;
  2. resolve the target; an empty URI is `log` + `die 2 "CB_BACKUP_S3_URI is empty"` **after**
     the archive exists, so the local copy is kept;
  3. `PUT` the archive at `<prefix>/db/<YYYY>/<MM>/<DD>.age` (UTC date of the run);
  4. `PUT` `<prefix>/_latest` whose body is exactly `<key>\n`;
  5. prune: keep the 30 lexicographically greatest keys under `<prefix>/db/`, `DELETE` the
     rest; a failed prune logs `warn: cannot prune <key>` and does not fail the run;
  6. verify: `HEAD` the archive, require `200`, `content-length` equal to the local byte size
     and `x-amz-meta-sha256` equal to the sidecar hex; `GET` `_latest` and require the body to
     equal `<key>\n`. A failure is `die 6 "cannot verify <key>"`.

  On success print exactly one more stdout line: `uploaded <key>` (the existing
  `archive <path>` line stays first). Exit `0`.

- **`--fetch KEY`** writes the object at `<KEY>` (relative to the target) to **stdout as raw
  bytes**; all diagnostics go to stderr. It short-circuits **before** the database check, the
  recipient check and the archive code, exactly like `--verify` does. `Content-Length` is
  verified against the bytes read (`die 6 "short read <KEY>"`). Exit `0`, `2` or `6`. No
  `archive`/`uploaded` line.

- **KEY validation** (both `--fetch` and the upload keys): `^[A-Za-z0-9._/-]+$`, no `..`
  segment, no leading `/`, never a URL. A bad key is `die 2 "<KEY> is not a valid object key"`.

### S3 wire contract (implemented once, inside `backup.sh`, in the existing inline-Node style)

- **Target:** `s3://<bucket>[/<prefix>]`; a trailing `/` is dropped. Object URL is path-style:
  `<endpoint>/<bucket>/<key>`, each segment percent-encoded except `/`.
- **Endpoint:** `CB_BACKUP_S3_ENDPOINT`, else `https://s3.<region>.amazonaws.com`.
- **Region:** `CB_BACKUP_S3_REGION`, else `AWS_REGION`, else `AWS_DEFAULT_REGION`, else
  `eu-west-1`.
- **Credentials, first match wins:**
  1. `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` (+ `AWS_SESSION_TOKEN` if set);
  2. IMDSv2 at `${AWS_EC2_METADATA_SERVICE_ENDPOINT:-http://169.254.169.254}`:
     `PUT /latest/api/token` with `X-aws-ec2-metadata-token-ttl-seconds: 21600`, then
     `GET /latest/meta-data/iam/security-credentials/` for the role name, then
     `GET /latest/meta-data/iam/security-credentials/<role>` and read
     `AccessKeyId` / `SecretAccessKey` / `Token`;
  3. neither → `die 2 "AWS credentials are empty"`.
  A credential with a session token sends `x-amz-security-token` on every request.
- **Signature:** AWS Signature Version 4, service `s3`, terminal `aws4_request`, headers
  `host`, `x-amz-date` (`YYYYMMDDTHHMMSSZ`), `x-amz-content-sha256` (lowercase hex SHA-256 of
  the request body; the empty-body hash for GET/HEAD/DELETE), plus `x-amz-security-token`
  when present. `Authorization: AWS4-HMAC-SHA256 Credential=<akid>/<yyyymmdd>/<region>/s3/aws4_request, SignedHeaders=<lowercase, semicolon-separated>, Signature=<hex>`.
- **PUT extras:** `x-amz-meta-sha256: <hex>` and `content-length`.
- **LIST:** `GET <endpoint>/<bucket>?list-type=2&prefix=<prefix>/db/` (percent-encoded query),
  parsed for `<Key>…</Key>`, following `NextContinuationToken` while `IsTruncated` is true.
  Keys are opaque strings; a key that does not match `^db/\d{4}/\d{2}/\d{2}\.age$` is left
  alone (never deleted).
- No other network host is contacted by any of this. `age`, `tar`, `node` remain the only
  binaries `--verify` needs; `--fetch` and `--upload` need `node` only for the transfer.

### `ops/vm/restore.sh`

```
usage: restore.sh (--from ARCHIVE | --remote KEY | --latest) [--db FILE] [--identity FILE]
                  [--plaintext] [--force] [--verify] [--s3-uri URI] [--root DIR] [--help]
```

- `--from FILE` keeps today's behaviour byte for byte (local file, existence check, `die 6`
  on a bad archive, `die 2` on an existing database without `--force`).
- `--remote KEY` materialises the object through `backup.sh --fetch KEY` into a temporary
  file inside the script's existing `mktemp -d` and then continues exactly as `--from` does.
- `--latest` reads the body of `_latest` (trimmed) and behaves as `--remote` with that key; an
  empty body is `die 6 "_latest is empty"`.
- Exactly one of the three is required. None → `exit 2` printing the usage line (the current
  message `usage: restore.sh` must survive: one existing test greps it).
- Both remote modes require a non-empty target (`CB_BACKUP_S3_URI` or `--s3-uri`); empty is
  `die 2 "CB_BACKUP_S3_URI is empty"`. `--s3-uri` is forwarded to the `backup.sh --fetch`
  call. Transfer failures are `exit 6`.
- `--verify` still prints `verify ok runs=… jobs=… routines=…` and writes no database.
- The success line stays exactly `restored <db> runs=<n> jobs=<n> routines=<n>`.

### `ops/vm/spot-notice.sh`

```
usage: spot-notice.sh [--once] [--interval SECONDS] [--endpoint URL] [--state DIR]
                      [--backup-script FILE] [--help]
```

- Defaults: `--interval 30`, `--state /var/lib/codebox/spot-notice`,
  `--backup-script /usr/local/lib/codebox/backup.sh`,
  `--endpoint ${AWS_EC2_METADATA_SERVICE_ENDPOINT:-http://169.254.169.254}`.
- Each poll: `PUT <endpoint>/latest/api/token` (IMDSv2, TTL 21600) with `curl --max-time 2 -s`;
  then `GET <endpoint>/latest/meta-data/spot/instance-action` with
  `X-aws-ec2-metadata-token: <token>`.
  - `404` → no notice. `--once` prints `no spot notice` to stderr and exits `0`; loop mode
    prints nothing and sleeps `--interval`.
  - `200` → read `time` from the JSON body with inline `node` (fall back to the raw body if
    `time` is absent). Marker path:
    `<state>/final-<time with every character outside [A-Za-z0-9] replaced by ->.done`.
  - `401`/`403` → `--once` `die 6 "metadata token rejected"`; loop mode
    `log "warn: metadata token rejected"` and keep polling.
  - Any other status → `--once` `die 6 "metadata http <code>"`; loop mode
    `log "warn: metadata http <code>"` and keep polling.
- Exclusivity: `mkdir -p "$state"`; `exec 9>"$state/lock"; flock -n 9 || exit 0` — a second
  concurrent invocation does no work.
- Marker present → `log "notice <time> already handled"`, exit `0`, **no backup**.
- No marker → run `"$backup_script" --upload`. On success write the notice body to the marker
  and `log "final backup for <time>"`, exit `0`. On failure leave no marker and exit `6`
  (the unit retries).
- After a successful final backup the script exits and the unit does not restart it.
- Its only network targets are `--endpoint` and the S3 endpoint reached through `backup.sh`.

### Log and exit lines (observable)

- stdout: `archive <path>`, `uploaded <key>`, `verify ok …`, `restored …` — nothing else.
- stderr: every existing `codebox: …` line, plus `warn: plaintext backup`, `warn: cannot prune
  <key>`, `notice <time> already handled`, `final backup for <time>`, `no spot notice`.
- Exit codes: `0`, `2`, `6` only. `1` is never used on purpose.

### Data

| Key | Shape | Unit / default |
| --- | --- | --- |
| object key | `<prefix>/db/<YYYY>/<MM>/<DD>.age` | UTC date of the run; `prefix` = the URI path without slashes |
| `_latest` | object at `<prefix>/_latest`, body `<key>\n` | one line, UTF-8 |
| local checksum | `<archive>.sha256`, body `<hex><space><space><basename>\n` | lowercase hex, SHA-256 of the archive bytes |
| remote checksum | `x-amz-meta-sha256` on the uploaded archive | same hex |
| manifest | `{ version, createdAt, dbBytes, encrypted }` | unchanged |
| spot marker | `<state>/final-<sanitised-time>.done`, body = the notice JSON | `state` defaults to `/var/lib/codebox/spot-notice` |
| spot lock | `<state>/lock` | `flock -n`, never deleted |

## 🧩 Configuration

All of these are **host variables**, never daemon configuration: they live in a
`systemctl edit` drop-in or the unit environment, never in `/etc/codebox/instance.env`, and
therefore get **no row in `docs/providers.md`** (the existing precedent for
`CB_BACKUP_AGE_RECIPIENT` and `CB_BACKUP_BUCKET`). Document them in `ops/vm/README.md` only.

| Key | Required | Default | Meaning |
| --- | --- | --- | --- |
| `CB_BACKUP_S3_URI` | for `--upload`, `--remote`, `--latest` | — | `s3://bucket[/prefix]`. Empty with `--upload` → exit 2 after the archive exists. |
| `CB_BACKUP_S3_ENDPOINT` | no | `https://s3.<region>.amazonaws.com` | Any S3-compatible endpoint, e.g. the OCI Object Storage compatibility endpoint. |
| `CB_BACKUP_S3_REGION` | no | `AWS_REGION`, `AWS_DEFAULT_REGION`, `eu-west-1` | SigV4 region. |
| `CB_BACKUP_AGE_RECIPIENT` | unless `--plaintext` | — | Unchanged. |
| `CB_BACKUP_AGE_IDENTITY` | for decrypt | — | Unchanged; never on the box by design. |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` | no | — | Explicit credentials; win over IMDS. |
| `AWS_EC2_METADATA_SERVICE_ENDPOINT` | no | `http://169.254.169.254` | IMDS base; the standard name, used by `backup.sh` and `spot-notice.sh`. |

`CB_BACKUP_BUCKET` is **retired**: remove it from the unit comment, the README and the `oci`
code path. `oci` is no longer needed by `backup.sh`.

No new dependency. The transfer uses Node's built-in `fetch`/`crypto` (Node 24) inside the
script; `curl` (already used by `keepalive.sh`) covers the IMDS calls. Neither adds a
package.
