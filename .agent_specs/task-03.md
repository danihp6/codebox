## 🔒 Contract

The public surface other tasks are written against **right now**.

**Global rules for every schema in this package**

1. `import { z } from 'zod';` — `zod` is the only runtime dependency, pinned exactly to
   `4.6.7` (no caret). Nothing else may be added to any `package.json`.
2. Every object schema is **strict**: an unknown field is a failure, never a silent strip
   (`docs/api.md` §1). Use `.strict()` (or `z.strictObject`) everywhere, including nested
   objects and inside unions. The single exception is the OpenAPI document's
   `components.schemas` entries, which are opaque JSON Schema and use `.passthrough()`.
3. No `any` in an exported signature. `unknown` plus a parse at the edge.
4. Timestamps are RFC 3339 **UTC with a `Z` suffix** only (`2026-10-24T18:03:11Z`);
   `2026-10-24T18:03:11+02:00`, `2026-10-24T18:03:11` and `2026-10-24` are rejected.
5. Ids are `prefix` + a non-empty alphanumeric suffix: `^<prefix>[0-9A-Za-z]{6,40}$`.
6. `src/index.ts` re-exports every public name below and nothing else. With
   `verbatimModuleSyntax`, types are re-exported as `export type { ... }` and values as
   `export { ... }`. Source and tests import siblings with the `.js` specifier
   (`./events.js`), the repo's ESM convention; Vite maps it to the `.ts` for a TypeScript
   importer. If the runner refuses (it should not), use `./index.ts` **in test files only** —
   tests are excluded from the build, so a `.ts` specifier never reaches `dist`.
7. Where this spec names a zod 4 API, the **behaviour** is the contract, not the spelling:
   if the pinned version calls it `z.iso.datetime()` or `z.string().datetime()`,
   `z.strictObject()` or `.strict()`, use what compiles against 4.6.7 and list the differences
   in the report. Never weaken a rule to make an API fit.

### `parse.ts`

The one place a zod failure becomes a typed error. No other file constructs one.

```ts
export interface ParseIssue {
  path: string;   // dotted, starts with the boundary: 'job.cron', 'events.3.data.delta'
  message: string;
  code: string;   // the zod issue code, e.g. 'invalid_type', 'too_small', 'custom'
}

export class ContractParseError extends Error {
  readonly boundary: string;
  readonly issues: readonly ParseIssue[];
  constructor(boundary: string, issues: readonly ParseIssue[]);
  /** The first issue, never undefined; `path` is the field that failed. */
  readonly first: ParseIssue;
}

export function parseOrThrow<T>(schema: z.ZodType<T>, input: unknown, boundary: string): T;
export function toParseIssues(error: z.ZodError, boundary: string): ParseIssue[];
```

Path rules, frozen:

- The root is the boundary alone: a missing `cron` in a job yields `path === 'job.cron'`.
- Array indices are numbers, joined with `.` (`'run.guardrails.2.id'`).
- A record key is joined verbatim (`'config.CB_BIND'`).
- `parseOrThrow` never rewrites `message`; only `parseConfig` redacts text for secret keys
  (see `config.ts`).

Validation rules the schema itself enforces (all pure, no filesystem, no clock at import):

1. `CB_SESSION_SECRET` is **required**; missing or shorter than 32 characters fails with
   `path === 'config.CB_SESSION_SECRET'`.
2. When `CB_ENV=production`: `CB_PUBLIC_URL` is required and must be an `https:` URL;
   `CB_BIND`'s host must be loopback (`127.0.0.1`, `::1` or `localhost`). A `0.0.0.0` bind
   fails with `path === 'config.CB_BIND'`.
3. Exactly-one GitHub auth mode is **not** enforced: App + PAT is accepted (the daemon logs
   a warning, the App wins) and neither is accepted (the daemon starts read-only). The
   schema only validates the shapes.
4. Numbers parse from strings; a non-numeric value fails on its own path.
5. `CB_ALLOWED_ORIGINS` defaults to a one-element list holding the origin of
   `CB_PUBLIC_URL` when the variable is absent and `CB_PUBLIC_URL` parses, else `[]`.
   `CB_VAPID_SUBJECT` defaults to the string `mailto:<CB_OWNER_EMAIL>` with the parsed key
   substituted when `CB_OWNER_EMAIL` is present, and to `null` when it is absent — which is
   why its type is `string | null`.
6. **No secret is ever echoed.** For any issue whose `path` names a key in
   `SECRET_CONFIG_KEYS`, `parseConfig` replaces the message with
   `'<KEY> is invalid'`. The thrown error's `String()` must not contain the value.
7. Shapes: `CB_BIND` and `CB_TUNNEL_METRICS` are `host:port`; `CB_PUBLIC_URL`,
   `CB_OPENCODE_URL` and `CB_GITHUB_API_URL` must parse as URLs; every `*_SECONDS`,
   `*_DAYS`, `*_HOURS`, `*_FILES`, `*_LINES`, `*_PORT`, `*_DEPTH`, `*_RUNS` and
   `CB_MAX_CONCURRENCY*` value is a non-negative integer; `CB_DAILY_COST_USD` is a
   non-negative number.

`parseConfig` reads nothing: it takes the environment as an argument. `parseConfig({})`
fails on `CB_SESSION_SECRET` and points at that key.

### `openapi.ts`


`openApiDocumentSchema` validates the 3.1 **shape**, not a hand-written copy of it:
`openapi` is the literal `'3.1.0'`; `info.title` and `info.version` are non-empty strings;
`paths` is a record of path → path item; a path item only holds the keys `get`, `post`,
`put`, `patch`, `delete`, `parameters`, `summary`; an operation has `operationId`
(unique across the document) and `responses` with at least one entry; `components.schemas`
is a record of name → `z.record(z.string(), z.unknown()).passthrough()`.

Two `superRefine` rules, both objective:

1. Every `$ref` string anywhere in the document matches `#/components/schemas/<Name>` and
   `<Name>` exists in `components.schemas` (walk the object recursively).
2. `paths` contains **exactly** this set, sorted:
