# design

The repository's design source and its prototype map. Tasks read the specs and tokens here; it is
the operator's input for the app tasks (L2 in `TODO.md`).

| File | What it is |
| --- | --- |
| `README.md` | This map: frame, route, feature folder and the import rules. |
| `import.json` | The import map: the file key, the page and one entry per routed screen (§7). An input, never generated. |
| `tokens.json` | The DTCG colour source of truth, Task-84's twelve values, mirrored by the app (§5). |
| `routes.json` | Generated by the command in §4: one `{"path", "screen", "component"}` per mapped frame. |
| `screens/<slug>.json` | Generated by the command in §4: one screen's spec, its three states and its export hash. |
| `exports/<slug>.png` | Generated by the command in §4: the frame's PNG at scale 2. |

The three generated families are written by the command in §4; they land at L6, with the
operator's token, and are never hand-edited.

The file the map describes is `codebox` in Figma, edited through the `figma-edit` plugin. It
holds the routed screens, the repository's two views (backlog and workers), the design session
and the agent cast, in two themes and three widths, re-cut on 2026-10-28 against
D44/D47/D51-D56: the unit is a work and one backlog item, the repository is the root and the
backlog file is the list. Dark is the default (`docs/app.md` §9); light exists for every mobile
screen; 1280 is the desktop layout. Do not commit the `.fig` itself — only the link below and
the exports.

**The workers view is a factory, not a chat.** The repository screen has two tabs, `Backlog` and
`Workers`. The workers tab draws four role rooms (`ORQ`, `ARC`, `DEV`, `QA`) with one face and
one task chip per subagent, a road in on the left and a belt out on the right. Its states are
four, not six: `queued`, `running`, `needs you` and `asleep`. A failed run is not a screen: the
failed package leaves on the belt with a red strap and the orchestrator blocks the task and
opens a decision, while the dev takes another task. A shipped run is not a screen either: the
work moves on and the crew sleeps until it is given work.

**The schedule screen is retired.** The repository's schedule is configuration, not a screen;
its three dark frames and three light frames were deleted on 2026-10-28.

## 4. Import and export

The command reads the committed map (§7), fetches one page of the file over the Figma REST API
and writes the three generated families in one pass:

```bash
node scripts/design/import.mjs --file <key>
```

| Flag | Meaning |
| --- | --- |
| `--file <key>` | The Figma file key (default: `FIGMA_FILE_KEY`). |
| `--map <path>` | The import map (default: `design/import.json`). |
| `--root <dir>` | The repository root to read and write (default: the working directory). |
| `--check` | Regenerate from Figma in memory, compare byte for byte and write nothing; exit 1 on any drift. |

The three families are `design/routes.json`, one `design/screens/<slug>.json` per route and one
`design/exports/<slug>.png` per frame with `snapshot: true`; the slug is the one `screenSlug`
derives from the screen name in §1 (`Repo · backlog` → `repo-backlog`), so a screen's spec and
its export share one slug and a task can name both.

A spec whose frame is measurable also carries a `layout`: the frame's box, its layout mode,
padding and item spacing, its regions (box, corner radius, stroke and the fill as a
`design/tokens.json` key) and its type scale — role, family, weight, size, line height and the
colour key. A colour that is not an exact token value, an `rgba(…)` or a hex outside the twelve,
projects `null` and is still measured by `coloursOutsideTokens`: the importer never invents a
key. A frame with no autolayout is projected with `inferred: true`, zero padding, zero gap and
its regions in reading order (y, then x). A frame with no direct child that has a box writes no
`layout` at all, so every spec written before the measurement keeps parsing.

The last stdout line is a one-line summary: `frames`, `mapped`, `unmapped`, `colours`,
`coloursOutsideTokens`, `routes`, `screens` and `exports`. `coloursOutsideTokens` is a
measurement, not a failure: a colour outside `design/tokens.json` prints its own line and the
exit code stays 0.

The image request asks for PNG at scale 2 and the bytes are stored untouched: no resize, no
re-encode. Keep every file under 400 kB — a frame that exceeds it has too many hidden layers,
not a bigger asset — and a diff that moves that bound is reviewed at L6. `--check` needs the
real token too, because it re-imports; it prints one `drift: <path>` line per differing artifact
and exits 1. The operator runs the command at L6 and the driver queue never gets this task: an
agent cannot pull 40 PNGs through its context.

## 5. Tokens

`design/tokens.json` is the source of truth: a DTCG document with Task-84's twelve values — the
surface, ink, brand, waiting and danger colours — and the one place a colour literal is born.
Every colour the app uses and every colour the design check measures comes from it; the app
mirrors it in `apps/app/src/theme/` for the stylesheet, and the Design System band repeats the
values for reading, never as the source (D52).

Light uses `#15803d` and `#b45309` for text and strokes: `#22c55e` on white is 2.1:1 and is
reserved for fills and dots.

## 6. Rules

- **A task names its spec.** A task that creates or changes a routed screen lists
  `design/screens/<slug>.json` and `design/exports/<slug>.png` as read-only inputs, with the
  caption of the frame it implements. The slug is the one `screenSlug` derives from the screen
  name in §1 (`Repo · backlog` → `repo-backlog`), so the spec, the export and the task cannot
  drift apart. A screen task that names no spec is not ready to launch.
- A new route adds one row to §1 in the same task that adds the route.
- A frame that stops matching the code is fixed in Figma or deleted; a stale frame is worse
  than no frame.
- A frame never shows a control the product does not have: no chat that writes without a
  target, no promote, no approval prompt, no scope chip.
- The header of a backlog is a **chat button**, never a `+`: the only way to create work is to
  talk, and the sheet asks for the target (backlog, design, or none for a read-only chat).
- **The workers view has two controls and no buttons per agent.** The `▤` and `🔔` chips are the
  only tappable chrome; a face is a target to its own log. A new per-agent button is a design
  regression.
- **State lives on the worker, not on the room.** `needs you` is a 20 px badge over the head of
  the worker whose task is blocked; the room keeps its normal fill.
- **Motion frames** live outside the routed bands: `25`/`25b` (truck, package and hand-off,
  smart animate in a loop) and `28`/`28b` (blink, 80 ms). `27` documents the four faces. A new
  animated flow adds its pair next to them and states the trigger.
- **The design session previews the repository's artifact** (D52) and never invents a canvas:
  `25` shows `design/` at a commit, its declared states and what is pending.
- **The generated artifacts are never hand-edited.** A change goes through the map and a
  re-import; a hand edit is drift that `--check` reports.
- **A screen's spec and its export share one slug**, so a task names one identifier and cannot
  pair the wrong pair of files.

## 7. The import map

`design/import.json` is the map the command reads. It declares the `fileKey` and the `page` the
import selects, then one entry per routed screen:

| Key | Meaning |
| --- | --- |
| `caption` | The frame name exactly as drawn in Figma; the join key between the page and the entry. |
| `screen` | The screen name from §1; `screenSlug` derives the spec and export file names from it. |
| `route` | The route path, as in §1. |
| `component` | The standalone component class that renders the route. |
| `states` | `loading`, `empty` and `error`, each a frame caption or `null`. |
| `snapshot` | `true` downloads the PNG and fills `snapshotSha256`; `false` writes neither. |

The map drives the output: adding a screen is adding an entry. A caption that is no longer on
the page is fatal — the command stops with `frame_missing` rather than writing a screen the file
does not have.
