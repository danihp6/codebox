# Decisions

Frozen decisions, in the order they were taken. A decision is not reopened by a task; it is
amended by a later decision that says which one it supersedes. Every other document cites
these IDs.

| ID | Decision | Why / consequence |
| --- | --- | --- |
| **D1** | The product is **Codebox**, binary `codebox`, short alias `cb`; daemon `cbd`; env prefix `CB_`; OCI prefix `cb-`. | A codebox is the box that holds the code and the agents working on it: literal, one word, and `cb` is a free command. Rejected: *Groundstation* (AWS Ground Station), *Deckhand*, *Patchbay*, *Interlock* (already used by agent tooling), *Pilotbox*, *Codecrate*, *Codehaven* (weaker, kept as fallbacks). |
| **D2** | This delivery is **documentation only**. | The first code batch is Batch 1 in `TODO.md`. No code, workflows or scripts are written before the design is reviewed. |
| **D3** | **Single operator, single tenant.** The hybrid app is the only client. No messaging-network integration in v1. | Removes an entire adapter surface, a moderation problem and a second identity system. Revisit only with a new decision. |
| **D4** | Client stack: **Angular 22 + Ionic Angular 9 + Capacitor**, standalone components, signals, PWA service worker. | Angular 22 is the active major (2026-06); Ionic Angular 9 supports 18–22. Ionic gives native-feeling navigation and Capacitor gives iOS/Android without a second codebase. |
| **D5** | The agent runtime is **OpenCode V2** (`opencode serve`) bound to **127.0.0.1**; the daemon is its only client. | No public agent port, no second auth surface. The daemon normalises events so the app never speaks OpenCode's protocol. |
| **D6** | One **`cbd` daemon** owns HTTP, SSE, scheduler, workspaces, git provider and the OpenCode supervisor. | A single process is simpler to operate on one VM than five services, and SQLite gives it one writer. |
| **D7** | **Node 24 LTS + TypeScript, ESM.** | Active LTS in 2026, native `fetch`, test runner and SQLite; no CommonJS interop. |
| **D8** | State in **SQLite (WAL)** via `node:sqlite`, migrations as numbered SQL. No ORM. | No native build step, portable backup, enough for one operator. If `node:sqlite` is still experimental on the target, the fallback is `better-sqlite3` behind the same store port. |
| **D9** | Each repository is a **bare clone cache**; each run gets its **own worktree** under `/srv/codebox/worktrees/<runId>`. | Parallel runs never share a working tree; cancellation is `git worktree remove --force`; the cache stays warm. |
| **D10** | Git provider is **GitHub App** first, with a fine-grained **PAT fallback**. A `GitProvider` port leaves room for GitLab. | App installation tokens are short-lived and scoped; the PAT path exists for a personal account that cannot install an app. |
| **D11** | Autonomy: every change lands on a **`cb/` branch + PR**, the repo's **gate** runs, and the run **auto-merges when every guardrail is green**. The owner explicitly accepted this risk. | This was chosen over manual merge. The guardrails in D12 are therefore load-bearing, not advisory. |
| **D12** | Auto-merge requires all of: local gate exit 0; GitHub required checks green; PR mergeable and base unchanged; diff within budget; no protected path; no `do-not-merge` label; repo policy `auto`; global `CB_AUTOMERGE=on`. Otherwise the PR stays open and the owner is notified. | A single unmet condition fails closed. The list is duplicated in `docs/jobs.md` and tested. |
| **D13** | Scheduling uses **5-field cron + IANA timezone**, DST-safe. A missed fire runs once if within `CB_MISFIRE_GRACE_SECONDS` (default 900), otherwise it is skipped and logged. | Predictable, no custom DSL, no silent double-runs. |
| **D14** | Run lifecycle: `queued → preparing → running → gating → pr_open → merging → succeeded`; terminal alternatives `failed`, `cancelled`. | Every transition is persisted as an event, so the app and the audit log agree. |
| **D15** | Concurrency: **1 run per repository, 3 globally** (configurable down, never up without a decision); both settings must be at least 1. | Sized for the 8 vCPU / 16 GB spot floor: three repositories with their agent, build and Chromium run together and the fourth waits in `queued`; two agents never fight over one repository. The measurement that confirms the sizing is the bring-up of Task-46, recorded in `docs/aws.md`. |
| **D16** | API is **REST `/v1` + SSE**, OpenAPI 3.1, cursor pagination, idempotency keys on mutations that start work. | SSE survives Cloudflare and mobile networks better than WebSockets for one-way events; REST is easy to test and generate clients from. |
| **D17** | App auth is **device pairing**: one-time code → device keypair → short-lived access token + refresh. Cloudflare Access is an outer layer, not the only one. | A stolen tunnel URL is not enough to command the box; a lost phone can be revoked individually. |
| **D18** | Exposure is **Cloudflare Tunnel only**; the daemon binds loopback. SSH is the only other door, restricted to the admin address. No 80/443 inbound. | Matches the OCI security model already proven in `pkm-randomlike`; removes certificate management and port scanning. |
| **D19** | Configuration is **environment variables prefixed `CB_`**, parsed with zod at boot, failing fast. Precedence: CLI flag > env > compiled default. No secrets in the repo. | One schema, one redaction list, one place to document. The full table is `docs/providers.md`. |
| **D20** | Secrets live in **the host's own store**: the four bundles in `/etc/codebox/secret-bundles.json` (`0600`, operator-written) when it exists, **OCI Vault** read by the instance principal on OCI otherwise; a `0600` env file is the development fallback. Nothing is baked into the image or user-data (amended by D42). | The image is shareable and rebuildable without carrying credentials, and the same image boots on a host whose identity has no Vault grant. |
| **D21** | The VM image is **one provider-neutral Ubuntu 24.04 arm64 image** built with **Packer** from a per-host source (`oracle-oci`, `amazon-ebs`); **no secrets are baked**. The app is installed from a signed release artifact (amended by D42). | Reproducible images, fast boot, no snowflake instance, and one artefact for both hosts. Details in `docs/vm-image.md`. |
| **D22** | All OCI resources use the **`cb-` prefix** and the retry logic is extracted from `pkm-randomlike` into `ops/oci/` with `CB_OCI_*` variables. | The action is reusable and no longer tied to the game project. Inventory in `docs/oci.md`. |
| **D23** | Observability: structured JSON logs, a persisted event stream per run, `/v1/health`, `/v1/telemetry`, `cb doctor`. No external APM in v1. | One operator can read `journalctl`, the app's run timeline and the SQLite ledger without running a monitoring stack. |
| **D24** | **English** for docs, code, identifiers, commits and the default UI; **Spanish** for the operator's chat and an available UI locale. | Matches the workspace convention and the owner's language. |
| **D25** | Branch name `cb/<runId>-<slug>`; commit trailer `Codebox-Run: <runId>`; commit author `codebox[bot]`. | Every merge is attributable to a run, even after the app's state is gone. |
| **D26** | **Protected paths** default to `.github/**`, `ops/**`, `infra/**`, `**/*.env`, `CODEOWNERS`, `.gitmodules`; a run touching one never auto-merges. Diff budget: 40 files / 2 000 changed lines. | Prompt injection and runaway refactors are the two realistic ways an auto-merge hurts. Both fail closed. |
| **D27** | Unattended agents may edit files and run bash **inside the worktree**; `webfetch` is denied; secret-bearing env vars are not passed to the job; network is best-effort restricted. | The agent needs to build and test, not to browse or read the operator's keys. |
| **D28** | Retention: runs 90 days, events 14 days, job logs 30 days, approvals 7 days after resolution, work messages 90 days. | Bounded disk on a 100 GB boot volume; configurable. |
| **D29** | Cost guard: `CB_DAILY_COST_USD` (default 10) and `CB_RUN_TIMEOUT_SECONDS` (default 5 400); a run that exceeds either is cancelled and reported. A per-account budget (D54) is a **stricter** stop that moves the run to the next account instead of cancelling it. | Auto-merge without a cost brake is an open wallet. One global cap plus a per-account quota keeps the bill bounded without turning a dry subscription into a lost night. |
| **D30** | Notifications use **Web Push (VAPID)** for the PWA and **Capacitor Push** (FCM/APNs) for native. No third-party chat network. | One event pipeline, two transports, no new identity. |
| **D31** | The app starts from the **official Ionic Angular starter** (tabs/sidemenu) and a small custom design system. Admin templates are references, not a base. | Bootstrap-first admin templates fight Ionic's navigation and safe areas; grafting them costs more than it saves. Options and licences in `docs/app.md`. |
| **D32** | Tests: **Vitest** for daemon packages and contracts, Angular's supported unit runner for the app, **Playwright** for web e2e; acceptance criteria are tagged `[unit]` or `[live]`. A `[live]` criterion states its measurement. | A criterion nobody can execute is not a criterion. The QA wave uses the tags to budget its browser time. |
| **D33** | Backups: nightly encrypted SQLite dump + config to OCI Object Storage, 30-day retention; a restore drill is part of the beta exit. | The instance can vanish (idle reclaim); the repo and the backup are the recovery path. |
| **D34** | `pkm-randomlike`'s OCI retry was **migrated to Codebox on 2026-10-24**, before parity, by operator decision. pkm is braked (`OCI_RETRY=off`), its `pkm-vcn`/`pkm-subnet` are retired and Codebox owns `ops/oci` and the chain. | The original "do not touch pkm until parity" clause was overtaken by the operator wanting the box launched now. The autopilot's OCI wait is not load-bearing for the game; the cost of two chains on one tenancy is a shared rate limiter. Task-32 is reduced to deleting the duplicate and the stale variables. |
| **D35** | No Kubernetes, no serverless, no managed queue in v1. | One VM, one process, SQLite. Add a queue only when a measured limit demands it. |
| **D36** | **Superseded by D44.** A chat session persists across messages and app restarts, bound to one repository and one OpenCode session; it never opens a PR and never merges. | Chat is exploratory work with context; a run is a transaction. Keeping them separate is what made "promote to run" meaningful. D44 removes chat as a unit: the conversation belongs to a work, and the work's runs are the transactions. |
| **D37** | The **source repository is public**. Secrets stay out of the tree (D19, D20) and are held by Actions and OCI Vault. | Public repositories get free Actions minutes, which is what lets the OCI wait and the agent loop run around the clock. The exposure is the source, the docs and issue text, not a credential; if the repository ever goes private, `docs/agent-ci.md` §11's allowance check becomes load-bearing again. |
| **D38** | **Superseded by D44.** Two schedules, one clock: a **Job** was a repo transaction and a **Routine** a chat schedule (`prompt` answers in the chat, `reminder` is push only). Routines were created by the chat agent through a daemon tool; unattended runs never got that tool. | D44 makes a schedule an attribute of a work, so the routine branch — and the "a schedule without a repository produces a chat" case — disappear. `reminder` survives only as a notification with no work and no model cost. |
| **D39** | Idle reclamation is answered by **measuring and doing real work, never by a fake burner**: a host timer runs a bounded liveness pass (`cb doctor`, `cb prune`, a loopback health probe) and appends the CPU, memory and network reading it took, so the operator can see how far the box is from Oracle's thresholds. D33 still owns a vanished instance. | Oracle reads the **95th percentile over seven days**, so a spike every few hours cannot move it; the only way to clear it with synthetic load is roughly an hour a day of deliberately burned CPU, which games an Always Free rule and buys nothing. Evidence plus the box's own housekeeping is honest, costs no tokens and turns a guessed risk into a visible one. |
| **D40** | Request controls are **enforced in the daemon**: a 1 MiB body cap and a `CB_ALLOWED_ORIGINS` match on every `/v1` path, four security headers on every response, and two in-memory per-device budgets (120/min on `/v1`, 10/min on the run-creating routes) taken in the auth middleware before the handler. The secret scan is a **gate step**, not a ninth guardrail: a hit fails the run as `gate_failed` before the branch is pushed. | `docs/security.md` §5 and `docs/api.md` §7 already promised these controls and nothing enforced them. Keeping the scan inside G1 leaves the D12 guardrail list — and every test, screen and decision that reads it — unchanged, while a credential still cannot reach a PR. The three long-running systemd units gain the sandbox block so the agent's process, not a container, is the isolation boundary. |
| **D41** | **Superseded by D44.** The routine tools reached a chat through a **loopback MCP server owned by the daemon**: one bearer token per chat session, bound to that chat and its repository, and the `mcp` descriptor travelled only in a chat session create body. A run session never received it. | With chat gone, the tool seam has no session to attach to: a schedule is a field of a work and is written by the operator through the API, not by the model. Keeping a model-writable schedule surface would turn prompt injection into a persistence primitive for no benefit. |
| **D42** | **One image, two hosts.** The image is Ubuntu 24.04 arm64 with **no provider baked in**: the builder and the secret source are per host, and both hosts are Terraform stacks under `infra/{oci,aws}`. The OCI Ampere box stays the primary target; an AWS spot box runs the same image while OCI A1 capacity is pending. | The A1 wait has no date, and OCI-only docs would make the shipped AWS path look unsupported. Keeping the artefact provider-neutral means one rebuild and one release cover both hosts, and a host swap is a stack plus the same first boot. Secrets follow the host: `/etc/codebox/secret-bundles.json` first, OCI Vault only where it exists (D20). The `infra/` split keeps each provider's static resources reviewable on its own; the OCI instance stays with `ops/oci/launch.sh` because no `apply` can wait for capacity. |
| **D43** | **Retired by D44.** There is no free chat and no scope conversion: no `free` → `repo` handoff, no `promote`, no re-injection of the last ten turns, no scope chip. The conversation is a work's thread and the work is bound to its repository from creation. | The handoff existed to delay one question — *is this code?* — and in a code-first product that question does not exist: a work has a repository or it is a note. Retiring it deletes a state machine, a handoff divider, two list signals and a class of "which session holds which context" bugs. |
| **D44** | **One unit: `Work`.** A work belongs to exactly one repository and represents **one backlog item**: a title, a prompt and its runs. It has **no schedule** and **no conversation**. Each run keeps one worktree and at most one PR (D11/D12); retrying is another run, never a resume. The `jobs` table stays retired and `runs.jobId` stays null. | Two separate moves finish the collapse: the conversation becomes a document editor (D55) and recurrence becomes a property of the repository (D56). What is left is the only thing the box actually does — take one item and ship it. Supersedes D36 and the whole routine branch of D38. |
| **D45** | **No interactive approval prompts.** The agent runs unattended with the tools it needs. The barrier is the **disposable worktree plus the gate**, and the agent's OS user **cannot read `/etc/codebox/`, the secret bundles or the SSH keys**. Anything that must leave the machine goes through the daemon, never through the agent's shell. | A prompt nobody can answer at 03:00 is not a control; it is a modal that ends up auto-approved. Moving the barrier to the filesystem removes the human from the loop without handing the model the secrets. This is a security change: `docs/security.md` and `docs/jobs.md` describe the new boundary in the same task, and the isolation is measured, never assumed. |
| **D46** | **A schedule's window is a self-relaunching loop**, not a cron: the next fire starts `cooldown` after the previous one **finished**, inside `[start, end]`, bounded by `maxFires` and `maxCostPerFire`. A missed fire is not caught up; a time that does not exist (DST gap) is skipped, never fired twice; a fire still working at `end` is allowed to finish; three consecutive failures pause the schedule. | "Every 20 minutes" read as wall clock and read as finish-plus-20 produce very different bills once a fire takes eleven minutes. Anchoring to the finish keeps the loop honest, and the caps are what make "the agent decides what to do next" survivable. |
| **D47** | **Three tabs: Dashboard, Repos, Settings.** Dashboard is the global inbox — *Needs you*, running, unreviewed, today's spend, health — plus **one block per repository**. **Repos is the work surface**: a repository opens on its backlog, then its works, then its gate, policy and design. Settings owns credentials, provider accounts, devices, notifications and about. | A tab is a promise that the operator goes there often. The operator has two real questions — *what needs me?* and *what is this repository doing?* — so the repository stops being a filter inside a chat list and becomes a destination. Supersedes the Chat tab of the retired D43. |
| **D48** | **Context is a per-work budget the operator can reset.** A work exposes its window usage and cost. `Compact` starts a new OpenCode session in the **same worktree** with a deterministic replay of the last ten turns and never deletes the transcript. Usage warns at 75% and 90%; at 95% the daemon **refuses** the turn with `context_full`. Never automatic. | Auto-compaction spends money nobody authorised and loses detail at the worst possible moment. Failing closed is the same rule as the guardrails: an explicit error beats a silent degradation. Because every run already starts a fresh session, a run boundary is the natural compaction point and `Compact` becomes the explicit manual escape hatch. |
| **D49** | **Provider connections are provisioned at runtime, through the mechanism each provider actually offers**: a GitHub App created by **manifest flow**, OAuth for user-data providers, and one key entered once for the providers that only sell keys. The daemon keeps every credential in an encrypted, **write-only** store and exposes `configured`, `lastFour` and `lastUsedAt` — never the value. `CB_*` stays the bootstrap path for what a browser cannot deliver: `CB_SESSION_SECRET` and the host's cloud identity. | Pasting a PEM into an env file over SSH is the step that turns a control plane into a chore, and it is where secrets end up in shell history and image builds. Amends D19/D20 rather than replacing them: boot still fails fast on a bad `CB_`, but connecting a provider no longer needs a redeploy. The price is a new privileged surface — an `admin` device can write secrets — so the store is encrypted at rest, audited, and unreadable through the API. |
| **D50** | **Credentials are generic; providers are not.** A credential is `{name, kind, value, expose}` with `expose ∈ daemon | tool | env`, write-only and never readable through the API. The agent reaches a third-party API only through an **integration** (`{name, baseUrl, auth, credentialId, allowedHosts}`) exposed as the `integration.request` tool: the daemon injects the header and refuses any host outside the allowlist. `expose = env` exists only for the model key, because OpenCode reads it from the environment at boot, and the UI marks it as visible to the agent's shell. OAuth is never generic — it needs endpoints and a registered client — so it stays a connector (D49). | A fixed provider catalogue is a wish list; the long tail is "a key for something I use". But a generic store the agent can read is an exfiltration primitive: one poisoned `AGENTS.md` and every secret is gone. Binding each credential to a host allowlist keeps the long tail usable without ever handing the model the keys. |
| **D51** | **One owner per fact, one object in the app.** The backlog file is the list; SQLite is the state. A work is `{spec, status}`: `spec` is derived from the repository's files (`TODO.md`, `.codebox/repo.yml`, `design/`) and cached by commit SHA; `status` is projected from events. The app receives one composed object and never sees two stores. Files declare, the daemon observes, and **no field is written in two places**. | Two lists of the same thing always diverge, and the divergence is silent. Splitting by ownership kills the duplicate without pretending git can hold a token stream: intent is reviewable and versioned, runtime is high-frequency and ephemeral. The backlog is then the plan *and* the prompt, because an item already carries its title, body and acceptance criteria. The same split applies to a schedule: declared in the repository, `paused` and `nextFireAt` in `status`. |
| **D52** | **Design lives in the repository; canvases are importers.** `design/` holds `DESIGN.md`, DTCG tokens, `routes.json`, one screen spec per route with its states (`empty`/`loading`/`error`) and snapshots. Figma, Penpot or OpenDesign import into it through a command that opens a PR; nothing syncs backwards. The gate validates tokens, routes and declared states — never pixels. | The agent does not implement from pixels, it implements from a spec, and a spec in the repo is diffable, reviewable and already in the worktree it reads. A vector canvas is a separate product and a second source of truth; importing it one way keeps the repository honest. A pixel diff is a test that always fails on fonts, viewport and antialiasing, so the gate checks what is deterministic. |
| **D53** | **The unit is `Work` (`works`), not `Task`.** `Task-<ID>` stays the identifier of a backlog item. | The agent pipeline already uses `Task-68` for its own items, so naming the product unit the same would print "Work Task-68" on every screen and in every conversation. `Work` is also the honest noun: it is what the box does. |
| **D54** | **Provider accounts are plural and fail over in order.** A provider is an adapter; an **account** is `{providerId, label, credentialId, priority, state, resetAt, usedToday}`. Selection takes the lowest priority with `state = active`. Failover triggers are classified, not guessed: `401/403` → `invalid`; `429` or a provider quota error → `exhausted` until the provider's reset instant, or a cooldown when it reports none; an operator-set per-account budget also stops it. The turn is retried on the next account only if **no tool call was emitted**; otherwise the run stops and resumes in a new session (D48). When every account is exhausted the run fails with `provider_exhausted` and notifies — it never queues silently and never degrades to a cheaper model without a decision. `opencode-go` is the first provider: OAuth or token, both write-only. | One subscription runs dry and the box stops; an operator with two is expected to want "use the other one". Making the account a first-class row is the only way to know which one is dry, what it cost and when it resets. Amends D50: `expose = env` can hold **one** key, so the environment stays the bootstrap fallback and rotation is the daemon's job. The hard stop at zero accounts is the same fail-closed rule as D48 and the guardrails. |
| **D55** | **A chat is an editor with one target, not a unit.** A session is `{target: backlog | design | schedule | work:<id> | repo, repoId, thread, branch?, pendingProposal?}`. The **target is the write boundary**: the backlog editor may only write `TODO.md`, the design editor only `design/**`, the schedule editor only `.codebox/schedule.yml`, the decision session only notes on its work (and may propose a backlog edit), and **`repo` — no target — is a read-only chat with the repository's context that writes and proposes nothing**. Every targeted session **proposes** a diff or a decision; a merge or the operator's tap disposes. A work has no composer: its screen is the run log, and a run that needs a person **ends** in `needs_decision` instead of waiting. | Chat as a unit carried a lifecycle nobody wanted — free, bound, promoted. As an editor it has one job per target, and the target doubles as the permission boundary, so a poisoned backlog cannot make an editor write code. Ending the run at a doubt keeps D45's promise: nothing hangs at 03:00. |
| **D56** | **A schedule belongs to the repository and consumes the backlog.** `RepoSchedule {repoId, mode: once | every | window, cron | window, selection: nextPending | refs[], maxFires, maxCostPerFireUsd, cooldownMinutes}`. A fire takes the next eligible item **in the order of the file** and opens a run of it; an item is eligible when it is unchecked, has no work in `queued`/`running`/`needs_decision`, and has not exhausted `maxAttempts`. `once` is a single fire, `window` is the D46 loop, and a manual *Run next* is the same selection without a schedule. **There is no schedule without a repository**: per-work schedules, routines and repo-less reminders are retired. | The backlog already carries the priority — its order — so the schedule only has to say *when* the box works, not *what* to work on. Putting it on the repository also fixes the double-scheduler problem D44 kept half-alive, and removing the repo-less reminder removes the last object that needed no work. |
| **D57** | **The design check is the second gate step, run after the secret scan and only on a green gate.** `colour_outside_tokens`, `route_without_component` and `snapshot_hash_mismatch` fail the run; `screen_state_missing` is report-only until L5 draws the missing frames, and a rule this build does not know is enforced. No `design/tokens.json` skips the step; a git failure is `design_scan: git_failed` and fails closed. Amends D52. | The check was a module nobody called (issue #75), so a green gate was not re-decided by it; and a null state is not yet a fact the agent can fix, because the frames it would name do not exist.
| **D58** | **The design spec carries measured geometry; no canvas is compiled into code.** `design/screens/<slug>.json` gains a `layout` block — the frame's box, its regions with position, size, fill, radius and stroke, and the type scale (role, family, weight, size, line height, colour) — read from the Figma REST API and written by the import command. The spec is what a dev implements and `design/exports/<slug>.png` is what QA compares, side by side. HTML exports, canvas-to-code plugins and generated markup are out of scope, and no second source of truth is created: the repository owns the spec, the canvas is an importer. | D52 says the agent implements from a spec, but four fields carry no size, no spacing and no type, so "implement the spec" still meant guessing — and the first thing that did not match was the typeface, which no document recorded. Measured geometry is the same information a Dev Mode inspection gives, as data: diffable, reviewable, small enough to read inside a worktree, where an exported HTML page is thousands of lines of absolute positions that invites copying a layout that does not respond. The pixel comparison stays out of the gate for the reason D52 gives; it is a review step, with the export beside the screen. |
| **D59** | **The prototype is the head of the queue, and four rulings follow from it (2026-10-30).** (1) No screen task is cut before its `design/screens/<slug>.json` and `design/exports/<slug>.png` exist and the spec carries `layout` (D58); a screen built from the contract alone is **re-aligned**, never extended, and nothing is cut while the design track is open — `L2 → L5 → L6 → L7` waits for the operator, and the two tasks that draw no page wait with it. (2) The repository keeps **two tabs**, `Backlog` and `Workers`: `/repos/:id/schedule` and `/repos/:id/design` are retired, the schedule is configuration (D56) and opens in a sheet over the backlog, and the design preview stays in its session (D55). (3) **Desktop is out of v1**: the eight screens without a desktop frame stay that way until after the beta; 320 px and the interaction states are the criterion. (4) The repository list's `pending · running · merged` are **contract fields** (`Repo.counts`), computed by the daemon in the list query, never counted per row by the client. | A page written from a contract gets the fields and the states right and the drawing wrong, so every later task pays for the layout twice and QA has nothing to compare — eleven screens were built that way before this record. The two-tab ruling is what `design/README.md` §2 already drew, so the code was the outlier; the counts are the D51 rule again, one writer per fact. Desktop can wait because the operator works from a phone: a 1280 layout nobody opens is not a criterion. |

## Frozen values

These names are contract. A task that needs a different one amends this section and the
documents that cite it.

### Paths

| Path | Contents |
| --- | --- |
| `/etc/codebox/` | `instance.env` (0600), tunnel config, no repository content. |
| `/var/lib/codebox/` | `state.db`, `events/`, `logs/`, `artifacts/`, `backups/`. |
| `/srv/codebox/repos/` | Bare clone cache, one directory per `owner__name`. |
| `/srv/codebox/worktrees/` | One worktree per run; deleted after retention. |
| `/opt/codebox/` | Installed release (daemon, app static build, migrations). |

### Environment prefix and core values

`CB_*` (full table in `docs/providers.md`). Defaults that other docs rely on:

| Key | Default |
| --- | --- |
| `CB_BIND` | `127.0.0.1:8787` |
| `CB_OPENCODE_URL` | `http://127.0.0.1:4096` |
| `CB_STATE_DIR` | `/var/lib/codebox` |
| `CB_REPO_ROOT` | `/srv/codebox/repos` |
| `CB_WORKSPACE_ROOT` | `/srv/codebox/worktrees` |
